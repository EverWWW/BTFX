# 分析超时保护设计

## 目标

避免无人体、人体不完整或内容异常的视频长时间占用算法进程，同时不改变正常分析流程。

## 方案

- 保留用户主动停止分析的现有行为，停止后返回待处理状态。
- 总分析超时以本地配置为基础，但有效值限制为 1 至 10 分钟；旧版本自动写入的 30 分钟不再生效。
- 算法启动后 60 秒仍未收到有效 stdout 状态包时，判定启动超时。
- `pose_estimation_side`、`pose_estimation_front` 等人体关键点识别阶段最长允许 5 分钟。
- 其他非终态阶段最长允许 2 分钟。
- 收到新阶段状态时重新计算该阶段时长；`completed` 和 `failed` 不参与阶段超时。
- 自动超时需要杀死整个算法进程树、归档失败目录、保存失败测量结果，并显示中英文原因。

## 非目标

- 不使用 OpenCV HOG 等上位机人体检测作为硬性校验，避免漏检正常视频。
- 不修改算法 TOML 输入结构和 stdout JSON 协议。
- 不替代算法端后续增加的抽帧人体预检。

## 验证

- 单元测试覆盖启动、姿态阶段、普通阶段、阶段切换、终态和总超时上限。
- 现有完整测试集保持通过。
